## ВЕРДИКТ: NO-GO на использование реестра в прод-мониторинге (как есть)

Причина: heartbeat-файл — это произвольный JSON без проверки. Агент (или любой процесс с доступом на запись) может сделать себя «вечно активным», а экспортёр не видит подделки. Пока есть P0-1, реестр не годится даже как сигнал для алертов.

Что нужно для GO (минимум): схема и валидация на входе, отказ от дат из будущего, сверка с git-коммитами по автору, retention с контролируемым ростом.

## Замечания

**P0-1. Подделка «активности»: дата из будущего = вечный active.**
`agents_exporter.py:37-40`: `updated_at` берётся как есть, без проверки диапазона. `:48`: `active = status != done and age < STALE_SEC`. При `age < 0` условие всегда истинно.
Воспроизведено (`audit_repro.py`, A-4 P0-1): файл с `updated_at=2099-01-01T00:00:00Z` → `lovii_agent_active{…} 1`, `lovii_agent_stale_seconds = −2.28e9`.
Любой процесс с записью в `~/LOVII/agents-registry/` может сфабриковать «работаю» навсегда. Сверки с истиной (git, процессы) в экспортёре нет.
**Фикс:** отвергать `updated_at > now + 60 с` и `started_at > updated_at` (счётчик `lovii_agent_invalid_total`); `age = max(0, …)`; добавить метрику `lovii_agent_git_commits_1h{agent,repo}` через `git log --author=… --since=1.hour` по репо, которое агент заявил; алерт «active, но 0 коммитов и 0 процессов за 60 мин» → подозрение (сверка, которую предлагает PLAN, развилка 3).

**P1-1. Имя файла и поле `agent` не связаны; `agent` — произвольная строка.**
`agents_exporter.py:43`: `agent = d.get("agent", basename)` — поле из JSON, не из имени файла. Файл `a.json` может объявить `agent="zcode"` и подменить чужой реестр.
**Фикс:** требовать `basename == agent`; regex `^[a-z0-9][a-z0-9_-]{0,39}$`.

**P1-2. Кардинальность и рост каталога не ограничены.**
(а) `agents_exporter.py:47`: `lovii_agent_stale_seconds{agent}` эмитится для **каждого** файла безусловно. Воспроизведено: 3 файла → 3 серии, растёт линейно с числом файлов; уникальные `agent` от агента — неограниченная кардинальность.
(б) Retention выключен по умолчанию (`:24`); `.trash` (`:50-53`) никем не чистится (`:13-16` — «чистку делает владелец/cron», нигде не описано).
(в) `collect()` вызывается в `do_GET` (`:60`). При `AGENTS_RETENTION=1` GET на :9119 двигает файлы — побочный эффект в scrape-пути.
(г) Файлы с битой датой молча пропускаются (`:41-42`): «мусор» не виден ни в одной метрике.
**Фикс:** агрегат + top-N вместо серии на файл; лимит числа файлов и метрика `lovii_agent_registry_files`; retention — отдельным cron, не в scrape; `.trash` с TTL 7 дней; метрика `lovii_agent_invalid_files`.

**P1-3. Наивные timestamp интерпретируются локальной TZ экспортёра.**
`agents_exporter.py:40`: `datetime.fromisoformat(...)` без `tzinfo` → `.timestamp()` трактует как local time. Воспроизведено: `2026-10-12T00:00:00` без зоны даёт `stale=29086` при TZ=UTC и `36286` при TZ=Europe/Amsterdam — сдвиг 2 ч.
**Фикс:** отвергать значения без `Z` или смещения; в протоколе AGENTS.md требовать ISO8601 с зоной.

**P1-4. Произвольный текст в `task` и `branch` попадает в метрики.**
`agents_exporter.py:45-46`: `task`, `branch`, `repo` берутся из JSON без валидации. Протокол PLAN — `task` = ID задачи (`SZ-xxx`), но агент может записать сумму, ИНН или имя клиента. Всё это уйдёт в Prometheus и на дашборд, которым пользуются через viewer (см. A-3).
**Фикс:** `task`: `^[A-Z]{2,5}-\d{1,6}$`; `branch`: `^[\w./-]{1,80}$`, иначе `invalid` и без лейбла; `repo`: из allowlist (4 репо).

**P2-1. `status = blocked` считается активным.**
`agents_exporter.py:48`: любой статус кроме `done` при свежем heartbeat → `active=1`. Заблокированный агент выглядит «работающим». Нужна отдельная метрика `lovii_agent_blocked`.

**P2-2. Порог молчания 30 мин — риск ложных срабатываний.**
`agents_exporter.py:22` (`AGENT_STALE_SEC=1800`) при обновлении раз в ~10 мин (протокол `PLAN.md` Ф-2) даёт запас ×3 — адекватно для heartbeat. Но протокол пишет «на значимых шагах», а один шаг LLM-агента может длиться дольше 30 мин без записи. Вывод: либо heartbeat на подшаги, либо порог 45–60 мин (см. A-6 строка 4).

**P2-3. Битые файлы не видны.**
`agents_exporter.py:33-36` и `:41-42`: `except … continue` без метрики и без лога. Агент, который пишет битый JSON, «молчит» без алерта. **Фикс:** `lovii_agent_invalid_files` + stderr-лог.

**P2-4. `started_at` не используется.**
Поле объявлено в протоколе (`:7`), но в метриках не участвует. Нельзя отличить «давно работает» от «только стартовал».

**P2-5. Retention и «аудит-след» противоречат друг другу.**
`agents_exporter.py:13-16` называет heartbeat «будущим audit-следом», но: (а) файл перезаписывается (`update`), история состояний теряется; (б) файлы не в git и не в бэкапе; (в) retention по умолчанию выключен, а при включении переносит в `.trash` на том же диске. Для следа нужен append-only журнал (см. A-5 строка 8).

## Ответы на вопросы issue

- **Q1 (подделка):** файл — только сигнал. Сверки «как предложено» (коммиты по `author` + процессы) достаточно при условии P0-1 и P1-1. Без git-сверки подделка возможна при любом сроке жизни файла.
- **Q2 (спам/зомби):** нет, схема не адекватна (P1-2). Нужны лимиты и retention вне scrape.
- **Q3 (конфиденциальность):** да, может (P1-4). Валидация на входе снимает риск.
- **Q4 (согласованность с AGENTS.md):** порог 1800 с согласован с периодом ~10 мин, но не с длинными шагами (P2-2) и не с наивным временем (P1-3). AGENTS.md в репо нет → нужна выгрузка.
