## ВЕРДИКТ: NO-GO на «юридически значимый след» (требование владельца)

Для **операционного** вопроса «что и когда деплоилось» след годен с оговорками. Для вопроса «кто изменил платёжные настройки» — **нет**: изменения вне git и вне деплой-скрипта не оставляют следа вообще.

Ответы на вопросы issue:
- **Q1 (дыры):** да, ручной SSH-правки прода, `.env`/compose, SQL и cron — **не покрыты** (P0-1).
- **Q2 (доверять ли `/opt` git):** **нет** как факту «что запущено». HEAD показывает checkout; `lovii-deploy` делает `reset --hard` и молча стирает ручные правки tracked-файлов (P1-4).
- **Q3 (достаточно ли для инцидента с платёжными настройками):** **нет**. Если настройки в БД или в `.env` — следа нет. Если в git — след есть, но его можно подделать (P1-2).

## Замечания

**P0-1. Ручной SSH-деплой не различим и не персонален.**
`stand_shas_textfile.sh:37-43` и `README.md:31`: деплой идёт через `ssh deploy@host "deploy <stack> <sha> <before>"`. CI и человек используют один пользователь и одну команду. В логе нет ни ключа, ни оператора. Вывод: «кто задеплоил» невозможно установить по следу. Для системы с банком/выводами это требование владельца не выполнено.
**Фикс:** личный ключ на человека; в `authorized_keys` — `command="/home/deploy/bin/lovii-deploy-wrap",restrict` с записью `SSH_ORIGINAL_COMMAND` и `fingerprint` в журнал; CI-ключ отдельный и помечен. Проверить на проде (**нужна выгрузка**).

**P0-2. Нет следа на правки прода вне деплой-скрипта.**
Строки 5–7 таблицы: `.env`, compose, SQL, cron. Ни одна из этих поверхностей не логируется и не лежит в git. Это ровно сценарий «непонятно кто изменил платёжные настройки» из issue.
**Фикс (минимум):** auditd на `/opt`, `/etc/cron*`, `/var/spool/cron`; Postgres `log_statement='ddl'`+`log_connections`; sha256 `.env` в textfile с алертом. Все три — существующие механизмы ОС и СУБД, новый стек не нужен.

**P1-1. Коммиты не подписаны, авторство подделываемо.**
`git log --format='%h %G?'` по `lovii-observability` (4 коммита) → `N` у всех, gpg в среде нет. Значит `author` — это текст, а не доказательство. При `vigilant mode` GitHub помечает неподписанные коммиты, но не блокирует их — нужна обязательная подпись (**нужна выгрузка**: настройки веток `lovii-tech/*`).

**P1-2. Связка «git-авторство + heartbeat + аннотации» не криптографична.**
Ни один из трёх источников не подписан и не защищён от записи тем же пользователем, что и агент. Heartbeat подделывается (A-4 P0-1), git-author подделывается (P1-1). Связка даёт совпадение, а не доказательство.
**Фикс:** подписанные коммиты (P1-1) + сверка git ↔ GitHub run ↔ deploy-log по `sha` (правило в A-6). Этого достаточно для разбора, но не для юридического доказательства.

**P1-3. Heartbeat перезаписывается, история теряется.** См. строку 8.

**P1-4. `git reset --hard` стирает следы ручной правки.**
`README.md:32-33`: деплой делает `git reset --hard $sha`. Если кто-то правил tracked-файл на проде руками, следующий деплой молча это стирает. След — только в reflog, который не экспортируется (строка 4).
**Фикс:** перед reset сохранять `git diff` в файл с временем и SHA (≈5 строк в `lovii-deploy`); экспорт reflog (строка 4).

**P1-5. Сопоставление «что задеплоено» по `rev-parse HEAD` — не факт.** См. вопрос Q2: HEAD = checkout, а не запущенный образ. Нужен SHA из запущенных контейнеров (A-2 P1-6).

**P2-1. `pb` в деплой-логе не объяснён.** `stand_shas_textfile.sh:37-41` его не использует. Если `pb` — ссылка на пайплайн/сборку, это хороший ключ для связки; нужно подтвердить на выгрузке лога.
